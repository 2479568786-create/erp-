# OZON ERP 采集插件（正式版）

由老 ERP（OZON精铺助手）采集插件 v1.3.1 改造，**已彻底断联老 ERP，唯一数据链路为本地新 ERP**。老 ERP 自 2026-09-06 起降级为测试款、不再维护。本目录（`ozon-erp/extension`）为工程内正式版；同级 `ozon-erp-extension-连接新ERP` 为同内容副本。

## v1.4.0 新增：商品图片采集

采集面板 SKU 列表下方新增「商品图片」网格区：
- 自动列出页面主图/规格图/详情图候选（缩略图网格，来源角标标注）
- 点选图片（首次打开默认选中全部主图），支持 全选 / 仅主图 / 清空
- 点击「🖼 采集图片到 ERP 图库」→ 由 **ERP 服务端下载**（绕开 1688/淘宝 CDN 防盗链与页面 CSP），落库到 ERP「我的图库」，标签自动带商品标题
- 后端端点：`POST /api/collect/images`（最多 20 张/次，单张 ≤8MB，超时 120s）

## v1.5.2 修复：采集补发机制（"已保存，ERP 恢复后自动补发"）

v1.5.1 存在缺陷：**提交采集失败 → 入队 → 重试 2 次后队列丢弃**，导致"ERP 恢复后补发"经常静默丢失数据。v1.5.2 修订：

- **补发队列**：`maxAttempts=0`（不限次数） + TTL 7 天 —— 失败入队的采集在 ERP 恢复前均保留（7 天后自动清理），不再因重试次数丢失。
- **更快补发**：不再只等 5 分钟 alarm。`CHECK_DESKTOP_STATUS` / `onInstalled` / `onStartup` 检测到 ERP 在线且有积压时，**立即** 触发 `processPendingRetry`（每次最多 10 条），补发成功后弹系统通知"已自动补发 N 条采集数据到 ERP"。
- **popup 状态**：在线时显示"ERP 已连接（N 条待补发，正在自动补发）"。

### 升级 & 使用步骤

1. `chrome://extensions` → 点 **刷新** 重新加载插件（必须！）→ 右上版本显示 **1.5.2**
2. 打开插件 popup → 确认显示 **「ERP 已连接」**（地址应为 `https://185.209.28.217`）
3. 若弹窗显示"待补发"，**无需操作**——插件在线即会自动补发到 ERP，并在补发成功后通知
4. 旧插件弹出"补发"不走通的同学，刷新插件即可

> 排查：若弹窗仍显示"ERP 未连接"，请先确认地址为 `https://185.209.28.217`，并检查服务器 HTTPS 服务状态。

## 后端配套

新 ERP 已新增兼容端点（`backend/routes/compat_routes.py`），响应结构对齐老 FastAPI 工作台：
- `GET  /api/config` — 在线状态 / 图片过滤参数
- `GET  /api/auth/me` — 登录状态
- `GET  /api/assignment/stores` — 采集归属店铺列表
- `POST /api/collection-contexts` — 确认采集归属批次
- `POST /api/collect/from-extension` — 采集入库（字段自动映射到新 ERP 采集箱，同链接幂等合并）

## 安装步骤

1. ERP 已上云（`https://185.209.28.217`），无需本地启动；本地部署仅用于开发调试（`start.bat`）
2. Chrome 打开 `chrome://extensions` → 开发者模式 → **刷新**（或重新加载已解压的扩展程序）→ 确认版本 1.5.2
3. 若装过老插件，建议先禁用老插件（两者数据链路不同，避免混淆）
4. 打开 1688 / 淘宝 / 天猫商品页 → 页面浮动条「一键采集」→ 数据进入云端 ERP 采集箱

## 注意事项

- 插件默认使用 HTTPS 云端地址；若曾手动保存旧地址，请在 popup 中改为 `https://185.209.28.217`
- 采集归属店铺在插件 popup 中选择，对应新 ERP「店铺管理」里添加的店铺
- 老 ERP 的「操作员/团队」概念未迁移，新 ERP 本地单用户，采集人默认「涂总」
